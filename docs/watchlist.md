# Watch list

Known approximations, shortcuts and untested corners. If something behaves strangely, check here first. Each entry says what was assumed, what shows up if it is wrong, and where the code is. Add an entry whenever a shortcut or guess goes in; delete an entry when it is fixed (the git log keeps it). Design questions for the owner live in [questions.md](questions.md).

## View and picking

- Pick depth uses distance to the camera position (`viewport.ts` `pick`, `nearestVertex`); in orthographic mode the right depth is along the view direction. Symptom: a hidden edge or vertex is picked in a crowded area.
- Edges and vertices count as visible within `1% + 12 px` of the face depth under the pointer (`depthLimit`). Symptom: edges just behind thin faces are pickable, or edges on grazing faces are not.
- Standard top/bottom views tilt the camera by 1e-4; clipping planes follow camera distance (`fitClipping`); switching projection keeps the apparent size at the orbit target.
- View at face (V): curved faces use the area-weighted mean normal; wrap-around cylinders and cones look along their axis from the camera's side; spheres and tori fall back to model centre to face centre, wrong for off-centre features.
- Settings: pick ranges are stored in the browser only, not in the document.
- Dev metrics (triangle counts, latency) show only with `?dev=1`. Follow-ups: tighter tessellation when zoomed in, enough segments on sketch arcs, mesh stats in Copy diagnostics.
- The selection carries over onto a drag's result on purpose (the new round faces stay selected). If faces show orange while nothing is selected, suspect `setRelated` in `viewport.ts`.
- Axes are drawn to 1.25 times the largest model coordinate (at least 25 mm) and resize only when a new mesh arrives; they are depth-tested.
- Open surfaces render like solids; free edges are not highlighted.
- Hide/isolate is view-only: hidden bodies still feed whole-model tools and exports.
- Body identity (S65) is matched by shape and bounding box after each operation, not by the operation's face history: same shape or same box and volume is the same body, else the most overlapping box, else equal volume (a moved body), else a lone leftover pair. A body that is moved onto a large overlap with another, or changed beyond recognition next to unchanged bodies, can swap or lose its id. Whole-body transforms match by position.

## Selection

- Box select samples visibility (up to 6 points per edge, 12 triangle centres per face) against the whole model: a thin sliver can be missed, large models will lag. Window needs every triangle of a face inside. The "window selects items not enclosed" report was fixed by rewrite, not by a confirmed root cause (`boxselect.ts`). Box select starts from the model only with Ctrl or from empty space.
- Edge ring over a face with more than four edges takes the farthest parallel straight edge and stops at faces with holes. Region outline counts an edge once if it borders exactly one selected face, so it also picks edges at open model boundaries.
- Edge loops of a face select every boundary loop (outline and holes). Shared-loop double-click uses the first other selected edge as partner and falls back to the smooth chain (tangent within `1 - 1e-4`).
- Hole and boss centres are blue dots that select the hole face; centres hide when the hole wall is in the way. A hole centre is the middle of the full cylinder's axis (`measure.hole_centre`); partial cylinders have none. Centre distance is the straight distance, so holes at different depths read larger than their axis spacing.
- Divide face drag: with the form open, pressing on the model places the dividing line instead of selecting (Cancel first). Orientation comes from the first 4 px; the line is parallel to a face axis only.
- Related-face chips match with `LINEAR_TOL = 1e-5`, `ANGULAR_TOL = 1e-6` (`relations.py`); per-tool defaults are `TOOL_RULES` in `main.ts` and saved per tool in the browser.
- Measure mode (M during a drag) shifts the drag distance if the view moves under the pointer.
- Eyedropper picks against the committed model (the preview is hidden while armed) and reads values by field name: names containing "radius" or "diam", else length/distance, else radius; angle fields read an Angle row. Other names get a length.

## Modeling

- Topology ids change after each operation; anything that keeps an id across edits (Edit last, chips) is re-derived. Symptom: an edit lands on the wrong face after undo/redo.
- Holes and bosses are edited by fusing or cutting cylinders; a hole partly cut by another feature resizes oddly. Resize hole takes a typed diameter and does not show the current one.
- Shell, draft, delete face and remove fillet use OpenCASCADE defeaturing/offset, which can fail or give degenerate results; only shell has a volume check. Check Model info when a tool reports success but nothing changed.
- `UnifySameDomain` runs after every tool and may merge faces you wanted separate or renumber them. Measured 0.4 s on a 231-face plate and it grows with face count (merge only near the change if large models feel slow). On very detailed solids (~2,000+ faces) it can produce invalid geometry; push/pull then keeps the plain boolean result.
- Push/pull on multi-solid files booleans only the containing solid; faces on different solids, or in open shells, are refused. Overlap between separate solids is not resolved. Bodies that end up overlapping are not fused or checked.
- Per-body rotate and scale pivot about the model origin, so a scaled body also drifts.
- Resize fillet on a variable fillet maps start/end radii to the kernel's edge ends, which may mirror the original; it offers itself on any non-planar face and says so when it is not a fillet. Fillet per edge labels rows by edge id (hard to match with many edges); start 0 leaves an edge sharp; clashing radii at a shared vertex fail the preview.
- Inset face offsets the outer loop or one inner loop (`loop` number, order as the face reports) with sharp joins; concave corners self-intersect on large insets.
- Resize hole also resizes same-size holes by default (owner chose this); moving a hole still moves one. Fix if reported: default off, or a hint on the chip.
- Emboss/Cut along surface takes a form distance (no drag) and fails where the offset fails (tight curvature, distance beyond the radius of curvature).
- Array tools fuse copies with the original (max 200); arrays act on the whole solid today (S49).
- Combine STEP places the file at its own origin. Mesh exports use a 0.01 mm chord tolerance.
- Patch fill tries tangent (G1) only where an edge has one neighbouring face and silently falls back to G0. Do not use `BRepFill.Face_s`: afterwards, fillets of unrelated shapes in the same process returned invalid geometry (cause unknown); bridge uses ruled ThruSections.
- Import repair fixes only negative-volume solids (`ShapeFix_Solid`); closed surface bodies become solids; open ones get `ShapeFix_Shell` and sewing at 1e-3 mm, else are named in the import warning. Part names from STEP can show as garbage for non-Latin text. Loose faces outside any shell are not checked.
- Any non-Operation exception becomes "<Tool> failed on this geometry (...)"; only a handful of OpenCASCADE exceptions have friendly text.
- Open decision, future release: how to work with multi-solid STEP assemblies (per-body selection and visibility, separate parts, what push/pull, fillet and combine do across bodies).
- Performance: resizing 400 equal holes took about 3.8 s (one boolean); no real progress, only the busy spinner.

## Sketching

- The solver is SolveSpace (py-slvs). Redundant constraints are reported as conflicts rather than ignored. Horizontal/vertical distance dimensions reorder their points for its sign convention. Circle tangency uses a hidden touching point and does not choose internal or external; a badly placed sketch can flip sides.
- Sketches are not kept after Finish sketch (only faces remain). Regions come only from closed loops: an open line across a loop does not divide it. A zone is imprinted only when inside one flat face; one sticking out becomes a loose face over the model (delete it). Loose faces are not solids; push/pull makes one (negative cuts), and STEP export writes faces.
- Face outline and hole centres are fixed reference geometry. Every sketch also gets fixed points at the origin, axis crossings and face centre.
- Projection of model edges is a snapshot of lines and circles/arcs square to the plane; tilted circles, splines and edges square to the plane are skipped without a message (S45).
- Snapping to a point-on-curve or midpoint adds a constraint (stays on the line when dragged; delete to free it). Alignment guides use points only. Axis-line snaps add no constraint, so the point can drift when dimensions change; use the fixed origin point for constraints.
- Rectangle corner options: size clamped to just under half the shorter side; the rubber band shows square corners; rounded rectangles do not reuse snapped corner points.
- Round corner works only where exactly two straight lines meet and drops dimension constraints on the old corner. Offset curve copies are unconstrained plain geometry; open chains offset to the left of the drawing direction. Polygons carry equal-side constraints only, so dragging a corner can skew them.
- Trim and extend handle lines only (crossings with lines and circles); the edited line loses its constraints and gets free end points. Extrude with several nested loops makes inner loops holes; crossing loops are not checked.
- Live size tags are read-only, no arc tag, values rounded to 2 decimals. Drag by body pins all points at the pointer offset, so rectangle sides stretch neighbours; only line and circle bodies were checked in the app.
- Unwrap: a chain is a path of flat faces and cylinders running one direction (a sharp fold unrolls like a bend); a cone must not reach its apex and unrolls under half a turn and cannot chain; regions wider than half a turn are unsupported; regions outside a chain strip are dropped; outlines are 48-point interpolated curves (areas exact). The unrolled sketch has no extrude, revolve or edge projection; its plane sits beside the model and does not follow later changes.
- Ctrl+Z inside a sketch undoes a sketch step, not the model. Escape leaves the sketch once there is nothing to cancel. Sketch dimensions redraw every frame (untested with hundreds). Sketch polygons, trim, extend and unwrap on cones/chains are mostly unit-tested, not hand-tested in the app.

## Keys and settings

- Bare keys need an engaged viewport (pointer over the view, a recent exit, or a click in it; `ENGAGE_GRACE_MS = 1500`). Symptom: a view key does nothing right after using a panel.
- Rules are enforced at assignment and load only. Digit view keys ignore Shift. Only the first chord shows as the hint; rebinding replaces all chords. Ctrl+K may clash with a browser's own search in browsers other than Chrome.
- Leaving the page warns whenever undo steps exist or a sketch is open (an export does not clear it); opening another file over edits does not warn.
- Touch gaps: hide, isolate, show all, look at face and see-through have a key or search entry but no visible button; right-click, hover and keyboard-only paths have no touch equivalent.
- Touch sizing is a CSS rule for coarse pointers only (40 px targets for the bar, tool strip, view controls, Tools handle and search rows); not tried on a real touch screen. The Getting started card and search chips have no touch-specific layout.
- Search ranking: loose letter matching only for queries of 3 letters or fewer; tool keywords are a fixed table in `search.ts` keyed by tool id pattern, so new tools may need words added. Recent commands are stored by label, so renamed commands drop out of the recent list.
- Dimension overlap avoidance estimates text width from the character count (`dimensions.ts`); the first dimension drawn wins.
- Tool-usage counts live in core memory and reset on restart or reconnect; surfaces are `strip`, `search`, `drawer`, `keys`, `drag`, `other`; sketch tools are counted as `sketch_<tool>`, `sketch_extrude`, `sketch_revolve`, `sketch_finish`.

## Platform and release

- Windows build only was produced and smoke-tested locally; CI runs on all four targets (the `macos-15-intel` label is unverified). Bundle about 360 MB. Smoke tests do not cover the GUI, the browser opening, SmartScreen or Gatekeeper. A running `pliable-server` locks `core/.venv`; build in a separate env via `UV_PROJECT_ENVIRONMENT`.
- The launcher exits 20 s after the last tab disconnects, so a sleeping laptop can close the app. Websocket keepalive pings are off so a long operation holding the GIL cannot drop the connection.
- All releases on a machine share one per-user data folder (`%LOCALAPPDATA%\Pliable` on Windows) for autosave and the notice. A session written by a newer format is neither offered nor deleted, so these can accumulate. Optional fix if asked: a `portable.txt` marker beside the app keeps data beside it.
- Autosave liveness is a 30 s heartbeat plus a pid check: a hung process that still heartbeats counts as live, and a reused pid can make a dead session look live for up to 30 s. A release using the old flat layout writes beside the new folders and is adopted as an old session.
- Diagnostics scrubbing is a regex (`diagnostics.py` `scrub`): a path with spaces or a name inside other text could slip through (the dialog shows the text before copying). The browser user-agent is included as is. Not checked on a tester's machine.
- `THIRD_PARTY_NOTICES.md` was written from memory of each project's license; verify before the first release.
- The busy indicator appears after 400 ms for requests not on the quiet list (previews, sketch solves, lookups) in `app/src/client.ts`, shows elapsed seconds only.
- Orthographic still looks off to the owner (see decisions-log).
- Stretch (S36): move mode only re-fits flat neighbour faces with straight edges (edges tested for straightness at three sample points assuming even parametrization); curved neighbours are refused with an Insert fallback. No keep-angle toggle yet and no on-screen handle.
- Variable fillet interim radius (S47) works on one edge at a time and only as one extra point; the radius curve is interpolated by OCCT, so it can overshoot between points.
- Push/pull on a full cylinder wall now resizes it as a hole or boss (S60); a free-standing cylinder is read as a boss. Dragging such a wall in the viewport still needs the viewport to find the wall normal (viewport.ts is not in the kernel area).
- Save dialog for exports uses showSaveFilePicker where the browser has it and falls back to a download; the Import STEP replace warning is a plain browser confirm shown only when there are undo steps.

- Symmetric chip mirrors across the three mid-planes of the model bounding box only; parallel chip finds same-direction planar faces only. No tool declares the symmetric chip yet, so it highlights but does not feed a tool.
- Circular edge centre is recovered by matching hole centres (full holes and bosses only). Hole centre snaps appear only for hovered or selected holes.

- Pick ranges shrink on small faces (edge range = a quarter of the face's on-screen size, min 2 px; point range a third, min 3 px); the face size is computed from all its triangles on every pointer move, which may be slow on very large curved faces.
- Sketch constraints that a drawing tool adds (rectangle sides, snaps onto curves, tangent starts) are flagged `auto`, listed as automatic, lit up on hover and removable singly or all at once (provisional answer (a) to question 12). The unconstrained-drag guarantee is `_keep_unconnected` in `sketch.py`: geometry with no constraint path to the dragged point is restored after each solve. The floating report itself was never reproduced.
- Sketch On Face armed mode: pressing the button with nothing selected waits for the next face selection; only pressing the button again cancels (Escape belongs to the key router). A refused face records `sketch_on_face` as the last tool so the diagnostic report shows why.
- Projecting model edges into a sketch (`face_reference` with `project`) draws lines, full circles and arcs square to the plane. Tilted circles are not drawn (they need an ellipse entity, S44) and edges of other kinds are skipped; both are counted in the status line and their end points are projected as snappable fixed points. Projected axes are drawn 400 units either side of the projected origin only.
- Ellipse and spline are sketch entities whose constraints apply only to their points (centre and long-axis end; the points a spline passes through). The short radius of an ellipse is a plain number the solver does not hold, so it cannot be dimensioned or driven by constraints; offset, trim and extend refuse them. A projected tilted circle becomes an ellipse, but a tilted arc is still skipped (reported, end points snappable).
- Settled sketch solves also report how free each point is (green when the constraints place it) and, on failure, every constraint whose removal alone fixes the conflict. Both re-solve the sketch once per point or constraint, so they run only when nothing is being dragged; a sketch with hundreds of points will feel slow (untested). A point fixed in one direction and free in the other counts as free for colouring.
- Added sketch constraints: Collinear (two lines), Lock (every point of a shape, and a circle's radius, stay put), Point to line distance (kept on the side the point is on when set, so it cannot flip by itself), and Reference dimensions (a ticked box in the value prompt; shown in brackets and updated from the geometry, never solved). Pinning a point twice would be reported as a redundancy, so the solver pins each point once. A reference dimension keeps no value of its own and cannot be turned into a driving one yet.
- Edit selection (sketch panel): Move, Rotate, Scale, Mirror (across the last line selected, with symmetric constraints marked automatic), Mirror in either sketch axis (no constraints), Row of copies and Circle of copies. Copies carry geometry only, not the original's constraints. Moving without Copy shifts points in place and lets the constraints settle; if they refuse, the change is undone. Rotating and scaling ask for the centre in sketch coordinates (starts at the selection's middle); no pointer picking yet. Counts are limited to 200.
- New sketch tools: Circle by 3 points (existing points you snap to are put on the circle; the clicked points themselves are not kept), Arc by 3 points (ends are the clicked points), Slot (end centres then width; two tangent arcs of equal radius, no constraint keeps the ends parallel to anything), Point (a free point that snaps like any other).
- A sketch drag longer than 5% of the sketch's size is solved in up to 12 steps from where the geometry is (so it follows the same branch of a tangency instead of jumping to the other); a failed later step returns the last good one. A fast hand on a big sketch costs up to 12 solves per pointer move (untimed). Small tags (H, V, T, =, Fix, ...) mark where constraints act; they can be hidden from the constraint list, and crowded ones are left out.
- Typing a size while drawing (line, circle, rectangles, polygons): digits, a point and Backspace are captured before the key router, Enter places the next point that far from the last one in the pointer's direction, and a line, circle or plain rectangle also gets a dimension for it (a rectangle takes width, space, height; one number means a square). Escape clears the typed text first. A dimension that clashes with existing constraints is dropped and the shape kept.
- An ellipse's short radius can be dimensioned (Short radius; shown as a tag `r..` at the end of the short axis). It is a plain parameter the solver sets directly, so it cannot be tied to other geometry by equal, tangent or similar constraints, and no spline shape constraint exists. Full shape constraints would need a different solver (a planegcs wheel exists for Windows and Linux only, no macOS build, so it was not added).
- Split tool: cuts a line in two where clicked (not within 2% of an end). Direction constraints (horizontal, vertical, parallel, perpendicular, angle) go on both pieces; lengths, equal, tangent and midpoint on the old line are dropped; a line with no direction constraint gets an automatic collinear one. Check sketch lists points that nearly touch (closer than 0.5% of the sketch's size) and open line or arc ends (selected so they show); Join near points merges the near pairs, keeping a fixed reference point when one is involved. Open ends joined only by point-on or midpoint constraints are not reported.
- Sketch placement: with three vertices selected (or one straight edge and one vertex) the bar offers Sketch Through 3 Points / Edge And Point. The plane's x direction runs from the first point to the second, so which point was picked first matters for the sketch's orientation; there is no offset or angled plane from a face yet, and a curved edge is treated as its two end vertices.
- Sketch settings: opened by the gear at the right of the sketch card (its own window; saved in this browser's local storage under `pliable.sketchOptions2`): grid major and minor spacing in mm (`LENGTH_UNIT` in `app/src/units.ts`, to become selectable with a unit setting; minor 0 draws no light lines) and Automatic constraints (Off by default: drawing tools add none, so a rectangle is four free lines; From snaps only; Snaps and shapes keeps the old behaviour). The card's grid button shows the grid (off by default) and the next one turns on snap to grid (off by default; snaps to the minor spacing when set, else the major). Minor lines are drawn only when their spacing is below the major and gives at most 800 lines, and do not line up with the bold ones if the major is not a multiple of the minor. Snapping still places points exactly on an axis or curve; only the constraint is skipped. With Off, polygons, slots and rounded corners are not held in shape either. Entering a sketch no longer turns the view; the card's view button does. The drawing tools are in the top strip while a sketch is open (icons, the active tool shows its name; the strip wraps to rows when narrow); the card keeps constraints, editing and extrusion.
- The sketch origin is the middle of the face's extent along the plane's own axes (not the area centroid), and the axes drawn and snapped to are the sketch's own through that point, coloured by the nearest model axis; the model origin and its axis crossings stay as fixed snap points. On a face that is not square to its plane axes (a rotated or irregular outline) the middle of the extent is only approximately the visual centre. Hole tools still place from the area centroid.
- Kept sketches: Finish sketch keeps the sketch as its own object in the document and adds nothing to the model: no imprinted or loose faces (the owner asked for sketch geometry to stay separate from bodies). The list under the bodies shows or hides each sketch, edits it, renames on double-click, deletes it, and extrudes it; Undo and Redo carry sketches and they are autosaved (not in exported STEP files). Closed regions are drawn as tinted view-only profile faces (one teal tint used for nothing else) with the curves; open paths are kept as curves for later sweep and path-array tools. The profile faces cannot be picked or dragged yet: extruding is the Extrude button on the sketch's row (distance, join, cut or new body, both directions, preview) or the Extrude section while editing the sketch, and an extrusion from the editing card keeps the sketch in the same undo step. Kept sketch curves are not selectable or snappable yet. A sketch on unrolled curved faces stores those face ids, which may be stale after the model changes. The old `sketch_regions` request and `regions` option of `sketch_keep` remain in the core but nothing in the app uses them.
- Pull arrows (push/pull and other single-arrow drags) now start on the face and point outward, so the whole arrow stands outside the surface; they used to run back into the solid. While a sketch is open the model's handles are cleared. Typing digits on a dragged handle starts from the drag's current direction, so a face pushed in stays negative.
- Hint line (`app/src/hints.ts`) polls its context every 250 ms and sits above the chips bar; the M measure key is hard-coded in viewport.ts so it is not user-redefinable or shown from the keymap. Hint text for mouse actions is limited to Ctrl+click.
- Distances between two items put the dimension line on the upper side of the screen-space line; no way to drag it to another side yet.
- Measurement panel and leaders sometimes stopped updating until reload (owner report): not reproduced in a push/pull then select run. Defensive fixes in `main.ts`/`dimensions.ts`: measure replies no longer gated on a possibly stale `dragSels`, a failed update is logged once and cannot stop later frame updates, one undrawable dimension is skipped. If it recurs, check the console for "update failed".
- After a dropped connection the page resumes the dropped connection's model only if the same core process is still running (one parked document, not per tab); a restarted core falls back to the restore prompt or the demo.
- Push/pull handle sits at the face centre of mass, or the middle of the longest boundary edge when that point is off the face (`face_handle_point` in `ops.py`); a hole wall has no arrow and still drags along its radius.
- Handle grab range is 9 px and arm length 34 px (`manipulator.ts`, named constants); only the handle under the pointer shows its label.
- Rotate body handle slides along the ring tangent while dragged and snaps back onto the ring after each preview; the axis (0, 1, 2) is typed.
- Editable primitives keep a recipe (tool, values, rotation) that is checked by a shape signature (volume, face count, box within 1e-5 of the size); a change too small for that tolerance would not drop the recipe. A rotated primitive can be edited by size, but its position handles are hidden (the base point is in the primitive's own frame).

- Holes (S48): the opening is assumed flat and square to the axis (a hole through a sloped face is rebuilt with a flat cut); a plain through hole opens on the side that runs toward the negative axis direction; "through" is the depth that reaches the far side along the axis (`pass_length`, first exit of the axis line past the cut), so a body with a gap beyond the hole reports the first gap; a hole split into two half-cylinder faces is not recognised (treated as a slot); Edit hole edits one hole at a time and takes a countersink only when no counterbore is present; the drag-time dimension labels may lag one preview behind.
- Point-pick snapping offers every hole centre without the hidden-point test (a centre sits at mid-depth inside its hole, behind the face under the pointer), so a hole directly behind another feature on screen can be snapped to within 12 px (`reference.ts`).
- Handle-drag speed (S71, bracket demo plus an added box, synthetic 40-step drag at 16 ms): before, every pointer move queued a preview and the core answered them in order (about 80 ms each: 9 ms operation, 80 ms meshing), so the last reply of a 40-step drag arrived 2.8 s late and nothing showed until the pointer rested. After, one preview is in flight and the newest waits (latest wins): about 32 ms per round trip (7 ms operation, 17 ms meshing, 1 ms upload and show), and a move arrow slides the moving bodies on the client with no wait. Which bodies move is read off two consecutive previews of the same drag (their centres shift along the arrow), so the first two frames of a drag show the plain previews. Resize grips have no client-side approximation: their round trip is already about 32 ms, under the 100 ms target. Timing hooks: `window.__perf` (per-preview round trip, show time, core timings) and `window.__slid` (client slides) in `main.ts`.
- Preview meshes carry no per-edge drag directions (`tessellate(preview=True)`), so an edge picked on a preview cannot start a fillet drag until the preview is committed.

- Dimension editing (S56): the draft angle edit assumes the Z pull direction and only shows for flat faces within 45 degrees of upright; an edge length moves the flat face at its far end (flip: the near end) and so changes every edge on that face; a face distance or hole distance moves the last selected item (flip swaps) and does not move anything attached to it; the hole-to-face distance is not editable.
- Dimension editing: after a hole diameter or hole move edit the selection is empty (the tools track no face), so the dimension disappears until the hole is picked again.
- Move arrows are a fixed 80 px long on screen (`MOVE_ARM_PX` in `manipulator.ts`) and are drawn without depth testing, so bodies never hide them; picking uses screen distance only, before any body pick. Where a move arrow overlaps a resize grip (origin on a size handle), the rule is: the head half of the arrow wins, the arrow's start does not, so the grip stays reachable (`pickScore`). The owner grabs arrowheads away from grips, so this is a safety rule only.
- Push/pull cut: a negative distance that would remove the whole solid (a full face pushed through its own body) is refused with an error rather than leaving an empty model; in a drag the last distance that worked is kept. A cut larger than the material below the face cuts through and ignores the excess.
- Kept sketches: stored per history state (deep-copied, trimmed with the 50-step history), so a long session forgets sketches that exist only in forgotten states; sketch ids come from a counter saved with the autosave and are never reused. Sketches are not written into saved model files (open file/demo starts with none). `sketch_keep` with regions on a sketch with no closed zone keeps it and makes no faces (facesMade 0).
- Sketch requests carry the sketch's id as `sketch_id`, never `id`: over the socket every request has its own `id` (the reply is matched by it), which silently replaced a sketch id of the same name; unit tests that call `Session.handle` directly cannot see that, so one test now sends a correlation `id` too. Sketch placement: the main button is Sketch On Geometry. With a face it sketches on it; with one edge selected it starts a sketch on the plane square to that edge with its origin at the middle of the edge (the middle of a curved edge by parameter; for rail and path profiles); with three vertices, or an edge and a vertex, extra buttons offer a plane through them; normal to a curved edge uses its tangent there, and the plane's x direction is picked from the world axes.

- Sketch Select tool: a click adds to the selection and a click on a selected item removes it (no Ctrl/Shift needed); empty space clears it. Dragging an unselected item moves only that item; dragging a selected one moves the whole selection.
- Sketch solver requests leave out projected reference curves and fixed points no constraint uses (`forSolver`), because the solver has a limit on unknowns. A constraint to a reference curve keeps that curve in the request.
- Sketch box selection: dragging on empty space with the Select tool draws the same box as the 3D view (solid left to right = window, dashed right to left = crossing) and selects only sketch points and curves; it replaces the selection unless Ctrl/Shift is held. Curves are tested as 48-segment polylines.
- Leaving a sketch (Escape, Discard button, starting another sketch) asks first when a new sketch has drawn geometry or a kept sketch has changes; the page-unload warning is unchanged.
- Project model edges: a tilted arc or other curved edge becomes a spline through about 24 samples per turn (33 for other curves), so it is an approximation of the true ellipse arc; a curve seen edge-on is left as its end points.

## Random body colours

- Each body's colour depends only on its stable id: hue = id * 137.508 degrees (+20), saturation 32-42 %, lightness 62 % upward, raised per hue (up to 80 %) until contrast against #1b1d22 is at least 7:1. Blue hues therefore end up lighter than others. Tested for ids 1..500.
- After about a dozen bodies, hues of non-consecutive ids can sit close together; colours are distinct, not unique.
- The surface uses per-vertex colours on a white base, so lighting still applies; loose faces and sheets with no body keep the steel-blue. Colours are not saved in the document and there is no per-body override yet.
- In the body list the name colour overrides the grey of hidden bodies only when visible (hidden rows stay grey, no dot).
