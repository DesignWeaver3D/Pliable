# Watch list

Known approximations, shortcuts and untested corners. If something behaves strangely, check here first. Each entry says what was assumed, what shows up if it is wrong, and where the code is. Add an entry whenever a shortcut or guess goes in; delete an entry when it is fixed (the git log keeps it). Design questions for the owner live in [questions.md](questions.md).

## View and picking

- Pick depth uses distance to the camera position (`viewport.ts` `pick`, `nearestVertex`); in orthographic mode the right depth is along the view direction. Symptom: a hidden edge or vertex is picked in a crowded area.
- Edges and vertices count as visible within `1% + 12 px` of the face depth under the pointer (`depthLimit`). Symptom: edges just behind thin faces are pickable, or edges on grazing faces are not.
- Standard top/bottom views tilt the camera by 1e-4; clipping planes follow camera distance (`fitClipping`); switching projection keeps the apparent size at the orbit target.
- View at face (V): curved faces use the area-weighted mean normal; wrap-around cylinders and cones look along their axis from the camera's side; spheres and tori fall back to model centre to face centre, wrong for off-centre features.
- Settings: pick ranges are stored in the browser only, not in the document.
- Dev metrics (triangle counts, latency) show only with `?dev=1`. Follow-ups: tighter tessellation when zoomed in, enough segments on sketch arcs, mesh stats in Copy diagnostics.
- The selection carries over onto a drag's result on purpose (the new round faces stay selected). If faces show orange while nothing is selected, suspect `setRelated` in `viewport.ts`.
- Axes are drawn to 1.25 times the largest model coordinate (at least 25 mm) and resize only when a new mesh arrives; they are depth-tested.
- Open surfaces render like solids; free edges are not highlighted.
- Hide/isolate is view-only: hidden bodies still feed whole-model tools and exports.
- Body identity (commit `e64a3f9`) is matched by shape and bounding box after each operation, not by the operation's face history: same shape or same box and volume is the same body, else the most overlapping box, else equal volume (a moved body), else a lone leftover pair. A body that is moved onto a large overlap with another, or changed beyond recognition next to unchanged bodies, can swap or lose its id. Whole-body transforms match by position.

## Selection

- Box select samples visibility (up to 6 points per edge, 12 triangle centres per face) against the whole model: a thin sliver can be missed, large models will lag. Window needs every triangle of a face inside. The "window selects items not enclosed" report was fixed by rewrite, not by a confirmed root cause (`boxselect.ts`). Box select starts from the model only with Ctrl or from empty space.
- Edge ring over a face with more than four edges takes the farthest parallel straight edge and stops at faces with holes. Region outline counts an edge once if it borders exactly one selected face, so it also picks edges at open model boundaries.
- Edge loops of a face select every boundary loop (outline and holes). Shared-loop double-click uses the first other selected edge as partner and falls back to the smooth chain (tangent within `1 - 1e-4`).
- Hole and boss centres are blue dots that select the hole face; centres hide when the hole wall is in the way. A hole centre is the middle of the full cylinder's axis (`measure.hole_centre`); partial cylinders have none. Centre distance is the straight distance, so holes at different depths read larger than their axis spacing.
- Divide face drag: with the form open, pressing on the model places the dividing line instead of selecting (Cancel first). Orientation comes from the first 4 px; the line is parallel to a face axis only.
- Related-face chips match with `LINEAR_TOL = 1e-5`, `ANGULAR_TOL = 1e-6` (`relations.py`); per-tool defaults are `TOOL_RULES` in `main.ts` and saved per tool in the browser.
- Measure mode (M during a drag) shifts the drag distance if the view moves under the pointer.
- Eyedropper picks against the committed model (the preview is hidden while armed) and reads values by field name: names containing "radius" or "diam", else length/distance, else radius; angle fields read an Angle row. Other names get a length.

## Modeling

- Topology ids change after each operation; anything that keeps an id across edits (Edit last, chips) is re-derived. Symptom: an edit lands on the wrong face after undo/redo.
- Holes and bosses are edited by fusing or cutting cylinders; a hole partly cut by another feature resizes oddly. Resize hole takes a typed diameter and does not show the current one.
- Shell, draft, delete face and remove fillet use OpenCASCADE defeaturing/offset, which can fail or give degenerate results; only shell has a volume check. Check Model info when a tool reports success but nothing changed.
- `UnifySameDomain` runs after every tool and may merge faces you wanted separate or renumber them. Measured 0.4 s on a 231-face plate and it grows with face count (merge only near the change if large models feel slow). On very detailed solids (~2,000+ faces) it can produce invalid geometry; push/pull then keeps the plain boolean result.
- Push/pull on multi-solid files booleans only the containing solid; faces on different solids, or in open shells, are refused. Overlap between separate solids is not resolved. Bodies that end up overlapping are not fused or checked.
- Per-body rotate and scale pivot about the model origin, so a scaled body also drifts.
- Resize fillet on a variable fillet maps start/end radii to the kernel's edge ends, which may mirror the original; it offers itself on any non-planar face and says so when it is not a fillet. Fillet per edge labels rows by edge id (hard to match with many edges); start 0 leaves an edge sharp; clashing radii at a shared vertex fail the preview.
- Inset face offsets the outer loop or one inner loop (`loop` number, order as the face reports) with sharp joins; concave corners self-intersect on large insets.
- Resize hole also resizes same-size holes by default (owner chose this); moving a hole still moves one. Fix if reported: default off, or a hint on the chip.
- Emboss/Cut along surface takes a form distance (no drag) and fails where the offset fails (tight curvature, distance beyond the radius of curvature).
- Array tools fuse copies with the original (max 200); arrays act on the whole solid today (commit `abcc689`).
- Combine STEP places the file at its own origin. Mesh exports use a 0.01 mm chord tolerance.
- Patch fill tries tangent (G1) only where an edge has one neighbouring face and silently falls back to G0. Do not use `BRepFill.Face_s`: afterwards, fillets of unrelated shapes in the same process returned invalid geometry (cause unknown); bridge uses ruled ThruSections.
- Import repair fixes only negative-volume solids (`ShapeFix_Solid`); closed surface bodies become solids; open ones get `ShapeFix_Shell` and sewing at 1e-3 mm, else are named in the import warning. Part names from STEP can show as garbage for non-Latin text. Loose faces outside any shell are not checked.
- Any non-Operation exception becomes "<Tool> failed on this geometry (...)"; only a handful of OpenCASCADE exceptions have friendly text.
- Open decision, future release: how to work with multi-solid STEP assemblies (per-body selection and visibility, separate parts, what push/pull, fillet and combine do across bodies).
- Performance: resizing 400 equal holes took about 3.8 s (one boolean); no real progress, only the busy spinner.

## Sketching

- The solver is SolveSpace (py-slvs). Redundant constraints are reported as conflicts rather than ignored. Horizontal/vertical distance dimensions reorder their points for its sign convention. Circle tangency uses a hidden touching point and does not choose internal or external; a badly placed sketch can flip sides.
- Sketches are not kept after Finish sketch (only faces remain). Regions come only from closed loops: an open line across a loop does not divide it. A zone is imprinted only when inside one flat face; one sticking out becomes a loose face over the model (delete it). Loose faces are not solids; push/pull makes one (negative cuts), and STEP export writes faces.
- Face outline and hole centres are fixed reference geometry. Every sketch also gets fixed points at the origin, axis crossings and face centre.
- Projection of model edges is a snapshot of lines and circles/arcs square to the plane; tilted circles, splines and edges square to the plane are skipped without a message (commit `079cbfc`).
- Snapping to a point-on-curve or midpoint adds a constraint (stays on the line when dragged; delete to free it). Alignment guides use points only. Axis-line snaps add no constraint, so the point can drift when dimensions change; use the fixed origin point for constraints.
- Rectangle corner options: size clamped to just under half the shorter side; the rubber band shows square corners; rounded rectangles do not reuse snapped corner points.
- Round corner works only where exactly two straight lines meet and drops dimension constraints on the old corner. Offset curve copies are unconstrained plain geometry; open chains offset to the left of the drawing direction. Polygons carry equal-side constraints only, so dragging a corner can skew them.
- Trim and extend handle lines only (crossings with lines and circles); the edited line loses its constraints and gets free end points. Extrude with several nested loops makes inner loops holes; crossing loops are not checked.
- Live size tags are read-only, no arc tag, values rounded to 2 decimals. Drag by body pins all points at the pointer offset, so rectangle sides stretch neighbours; only line and circle bodies were checked in the app.
- Unwrap: a chain is a path of flat faces and cylinders running one direction (a sharp fold unrolls like a bend); a cone must not reach its apex and unrolls under half a turn and cannot chain; regions wider than half a turn are unsupported; regions outside a chain strip are dropped; outlines are 48-point interpolated curves (areas exact). The unrolled sketch has no extrude, revolve or edge projection; its plane sits beside the model and does not follow later changes.
- Ctrl+Z inside a sketch undoes a sketch step, not the model. Escape leaves the sketch once there is nothing to cancel. Sketch dimensions redraw every frame (untested with hundreds). Sketch polygons, trim, extend and unwrap on cones/chains are mostly unit-tested, not hand-tested in the app.

- Sketch drawing tools other than Line leave to Select after the first shape (`sketch.ts` `shapeDone`, commit 323c2c1). A smarter rule for when a tool may keep drawing, such as a modifier-click on the tool button, is not decided. Symptom: repeating a shape needs the tool picked again each time.
- Sketch typed sizes: slot, ellipse and arc sizes place the shape but are not kept as dimensions (only line, circle and rectangle are); the slot width typed is the whole width, the arc sweep is counterclockwise degrees (`sketchtyped.ts`, commit 323c2c1).

- Sketch point drag snapping (`sketchsnap.ts` `snapDragged`): only single-point drags snap, with the same 10 px reach as drawing; dragging whole curves or several items does not snap, and a point dropped on another point does not join it. Symptom: a dragged end that is meant to meet another point needs the Coincident button.

## Keys and settings

- Bare keys need an engaged viewport (pointer over the view, a recent exit, or a click in it; `ENGAGE_GRACE_MS = 1500`). Symptom: a view key does nothing right after using a panel.
- Rules are enforced at assignment and load only. Digit view keys ignore Shift. Only the first chord shows as the hint; rebinding replaces all chords. Ctrl+K may clash with a browser's own search in browsers other than Chrome.
- Leaving the page warns whenever undo steps exist or a sketch is open (an export does not clear it); opening another file over edits does not warn.
- Touch gaps: hide, isolate, show all, look at face and see-through have a key or search entry but no visible button; right-click, hover and keyboard-only paths have no touch equivalent.
- Touch sizing is a CSS rule for coarse pointers only (40 px targets for the bar, tool strip, view controls, Tools handle and search rows); not tried on a real touch screen. The Getting started card and search chips have no touch-specific layout.
- Search ranking: loose letter matching only for queries of 3 letters or fewer; tool keywords are a fixed table in `search.ts` keyed by tool id pattern, so new tools may need words added. Recent commands are stored by label, so renamed commands drop out of the recent list.
- Dimension overlap avoidance estimates text width from the character count (`dimensions.ts`); the first dimension drawn wins.
- Tool-usage counts live in core memory and reset on restart or reconnect; surfaces are `strip`, `search`, `drawer`, `keys`, `drag`, `other`; sketch tools are counted as `sketch_<tool>`, `sketch_extrude`, `sketch_revolve`, `sketch_finish`.

## Platform and release

- Windows build only was produced and smoke-tested locally; CI runs on all four targets (the `macos-15-intel` label is unverified). Bundle about 360 MB. Smoke tests do not cover the GUI, the browser opening, SmartScreen or Gatekeeper. A running `pliable-server` locks `core/.venv`; build in a separate env via `UV_PROJECT_ENVIRONMENT`.
- The launcher exits 20 s after the last tab disconnects, so a sleeping laptop can close the app. Websocket keepalive pings are off so a long operation holding the GIL cannot drop the connection.
- All releases on a machine share one per-user data folder (`%LOCALAPPDATA%\Pliable` on Windows) for autosave and the notice. A session written by a newer format is neither offered nor deleted, so these can accumulate. Optional fix if asked: a `portable.txt` marker beside the app keeps data beside it.
- Autosave liveness is a 30 s heartbeat plus a pid check: a hung process that still heartbeats counts as live, and a reused pid can make a dead session look live for up to 30 s. A release using the old flat layout writes beside the new folders and is adopted as an old session.
- Diagnostics scrubbing is a regex (`diagnostics.py` `scrub`): a path with spaces or a name inside other text could slip through (the dialog shows the text before copying). The browser user-agent is included as is. Not checked on a tester's machine.
- `THIRD_PARTY_NOTICES.md` was written from memory of each project's license; verify before the first release.
- The busy indicator appears after 400 ms for requests not on the quiet list (previews, sketch solves, lookups) in `app/src/client.ts`, shows elapsed seconds only.
- Orthographic still looks off to the owner (see decisions-log).
- Stretch (commit `daaa684`): move mode only re-fits flat neighbour faces with straight edges (edges tested for straightness at three sample points assuming even parametrization); curved neighbours are refused with an Insert fallback. No keep-angle toggle yet and no on-screen handle.
- Variable fillet interim radius (commit `53ee0b9`) works on one edge at a time and only as one extra point; the radius curve is interpolated by OCCT, so it can overshoot between points.
- Push/pull on a full cylinder wall now resizes it as a hole or boss (commit `a2e1742`); a free-standing cylinder is read as a boss. Dragging such a wall in the viewport still needs the viewport to find the wall normal (viewport.ts is not in the kernel area).
- Save dialog for exports uses showSaveFilePicker where the browser has it and falls back to a download; the Import STEP replace warning is a plain browser confirm shown only when there are undo steps.

- Symmetric chip mirrors across the three mid-planes of the model bounding box only; parallel chip finds same-direction planar faces only. No tool declares the symmetric chip yet, so it highlights but does not feed a tool.
- Circular edge centre is recovered by matching hole centres (full holes and bosses only). Hole centre snaps appear only for hovered or selected holes.

- Pick ranges shrink on small faces (edge range = a quarter of the face's on-screen size, min 2 px; point range a third, min 3 px); the face size is computed from all its triangles on every pointer move, which may be slow on very large curved faces.
- Sketch constraints that a drawing tool adds (rectangle sides, snaps onto curves, tangent starts) are flagged `auto`, listed as automatic, lit up on hover and removable singly or all at once (provisional answer (a) to question 12). The unconstrained-drag guarantee is `_keep_unconnected` in `sketch.py`: geometry with no constraint path to the dragged point is restored after each solve. The floating report itself was never reproduced.
- Sketch On Face armed mode: pressing the button with nothing selected waits for the next face selection; only pressing the button again cancels (Escape belongs to the key router). A refused face records `sketch_on_face` as the last tool so the diagnostic report shows why.
- Projecting model edges into a sketch (`face_reference` with `project`) draws lines, full circles and arcs square to the plane. Tilted circles are not drawn (they need an ellipse entity; projection was added in commit `079cbfc`) and edges of other kinds are skipped; both are counted in the status line and their end points are projected as snappable fixed points. Projected axes are drawn 400 units either side of the projected origin only.
- Ellipse and spline are sketch entities whose constraints apply only to their points (centre and long-axis end; the points a spline passes through). The short radius of an ellipse is a plain number the solver does not hold, so it cannot be dimensioned or driven by constraints; offset, trim and extend refuse them. A projected tilted circle becomes an ellipse, but a tilted arc is still skipped (reported, end points snappable).
- Settled sketch solves also report how free each point is (green when the constraints place it) and, on failure, every constraint whose removal alone fixes the conflict. Both re-solve the sketch once per point or constraint, so they run only when nothing is being dragged; a sketch with hundreds of points will feel slow (untested). A point fixed in one direction and free in the other counts as free for colouring.
- Added sketch constraints: Collinear (two lines), Lock (every point of a shape, and a circle's radius, stay put), Point to line distance (kept on the side the point is on when set, so it cannot flip by itself), and Reference dimensions (a ticked box in the value prompt; shown in brackets and updated from the geometry, never solved). Pinning a point twice would be reported as a redundancy, so the solver pins each point once. A reference dimension keeps no value of its own and cannot be turned into a driving one yet.
- Edit selection (sketch panel): Move, Rotate, Scale, Mirror (across the last line selected, with symmetric constraints marked automatic), Mirror in either sketch axis (no constraints), Row of copies and Circle of copies. Copies carry geometry only, not the original's constraints. Moving without Copy shifts points in place and lets the constraints settle; if they refuse, the change is undone. Rotating and scaling ask for the centre in sketch coordinates (starts at the selection's middle); no pointer picking yet. Counts are limited to 200.
- New sketch tools: Circle by 3 points (existing points you snap to are put on the circle; the clicked points themselves are not kept), Arc by 3 points (ends are the clicked points), Slot (end centres then width; two tangent arcs of equal radius, no constraint keeps the ends parallel to anything), Point (a free point that snaps like any other).
- A sketch drag longer than 5% of the sketch's size is solved in up to 12 steps from where the geometry is (so it follows the same branch of a tangency instead of jumping to the other); a failed later step returns the last good one. A fast hand on a big sketch costs up to 12 solves per pointer move (untimed). Small tags (H, V, T, =, Fix, ...) mark where constraints act; they can be hidden from the constraint list, and crowded ones are left out.
- Typing a size while drawing (line, circle, rectangles, polygons): digits, a point and Backspace are captured before the key router, Enter places the next point that far from the last one in the pointer's direction, and a line, circle or plain rectangle also gets a dimension for it (a rectangle takes width, space, height; one number means a square). Escape clears the typed text first. A dimension that clashes with existing constraints is dropped and the shape kept.
- An ellipse's short radius can be dimensioned (Short radius; shown as a tag `r..` at the end of the short axis). It is a plain parameter the solver sets directly, so it cannot be tied to other geometry by equal, tangent or similar constraints, and no spline shape constraint exists. Full shape constraints would need a different solver (a planegcs wheel exists for Windows and Linux only, no macOS build, so it was not added).
- Split tool: cuts a line in two where clicked (not within 2% of an end). Direction constraints (horizontal, vertical, parallel, perpendicular, angle) go on both pieces; lengths, equal, tangent and midpoint on the old line are dropped; a line with no direction constraint gets an automatic collinear one. Check sketch lists points that nearly touch (closer than 0.5% of the sketch's size) and open line or arc ends (selected so they show); Join near points merges the near pairs, keeping a fixed reference point when one is involved. Open ends joined only by point-on or midpoint constraints are not reported.
- Sketch placement: with three vertices selected (or one straight edge and one vertex) the bar offers Sketch Through 3 Points / Edge And Point. The plane's x direction runs from the first point to the second, so which point was picked first matters for the sketch's orientation; there is no offset or angled plane from a face yet, and a curved edge is treated as its two end vertices.
- Sketch settings: opened by the gear at the right of the sketch card (its own window; saved in this browser's local storage under `pliable.sketchOptions2`): grid major and minor spacing in mm (`LENGTH_UNIT` in `app/src/units.ts`, to become selectable with a unit setting; minor 0 draws no light lines) and Automatic constraints (Snaps and shapes by default since 2026-10-25; From snaps only; Off: drawing tools add none, so a rectangle is four free lines). The card's grid button shows the grid (off by default) and the next one turns on snap to grid (off by default; snaps to the minor spacing when set, else the major). Minor lines are drawn only when their spacing is below the major and gives at most 800 lines, and do not line up with the bold ones if the major is not a multiple of the minor. Snapping still places points exactly on an axis or curve; only the constraint is skipped. With Off, polygons, slots and rounded corners are not held in shape either. Entering a sketch no longer turns the view; the card's view button does. The drawing tools are in the top strip while a sketch is open (icons, the active tool shows its name; the strip wraps to rows when narrow); the card keeps constraints, editing and extrusion.
- The sketch strip has one Polygon tool (regular n-gon: centre, then a corner) instead of the fixed triangle, pentagon, hexagon and octagon buttons; the number of sides (3 to 64) is a field in the sketch card while the tool is active and is remembered with the sketch settings. The fixed shapes still exist in the code (and the typed-size and equal-side behaviour is shared) but are not offered.
- The sketch origin is the middle of the face's extent along the plane's own axes (not the area centroid), and the axes drawn and snapped to are the sketch's own through that point, coloured by the nearest model axis; the model origin and its axis crossings stay as fixed snap points. On a face that is not square to its plane axes (a rotated or irregular outline) the middle of the extent is only approximately the visual centre. Hole tools still place from the area centroid.
- Kept sketches: Finish sketch keeps the sketch as its own object in the document and adds nothing to the model: no imprinted or loose faces (the owner asked for sketch geometry to stay separate from bodies). The list under the bodies shows or hides each sketch, edits it, renames on double-click, deletes it, and extrudes it; Undo and Redo carry sketches and they are autosaved (not in exported STEP files). Closed regions are drawn as tinted view-only profile faces (one teal tint used for nothing else) with the curves; open paths are kept as curves for later sweep and path-array tools. The profile faces cannot be picked or dragged yet: extruding is the Extrude button on the sketch's row (distance, join, cut or new body, both directions, preview) or the Extrude section while editing the sketch, and an extrusion from the editing card keeps the sketch in the same undo step. Kept sketch curves are not selectable or snappable yet. A sketch on unrolled curved faces stores those face ids, which may be stale after the model changes. The old `sketch_regions` request and `regions` option of `sketch_keep` remain in the core but nothing in the app uses them.
- Pull arrows (push/pull and other single-arrow drags) now start on the face and point outward, so the whole arrow stands outside the surface; they used to run back into the solid. While a sketch is open the model's handles are cleared. Typing digits on a dragged handle starts from the drag's current direction, so a face pushed in stays negative.
- Hint line (`app/src/hints.ts`) polls its context every 250 ms and sits above the chips bar; the M measure key is hard-coded in viewport.ts so it is not user-redefinable or shown from the keymap. Hint text for mouse actions is limited to Ctrl+click.
- Distances between two items put the dimension line on the upper side of the screen-space line; no way to drag it to another side yet.
- Measurement panel and leaders sometimes stopped updating until reload (owner report): not reproduced in a push/pull then select run. Defensive fixes in `main.ts`/`dimensions.ts`: measure replies no longer gated on a possibly stale `dragSels`, a failed update is logged once and cannot stop later frame updates, one undrawable dimension is skipped. If it recurs, check the console for "update failed".
- After a dropped connection the page resumes the dropped connection's model only if the same core process is still running (one parked document, not per tab); a restarted core falls back to the restore prompt or the demo.
- Push/pull handle sits at the face centre of mass, or the middle of the longest boundary edge when that point is off the face (`face_handle_point` in `ops.py`); a hole wall has no arrow and still drags along its radius.
- Handle grab range is 9 px and arm length 34 px (`manipulator.ts`, named constants); only the handle under the pointer shows its label.
- Rotate body handle slides along the ring tangent while dragged and snaps back onto the ring after each preview; the axis (0, 1, 2) is typed.
- Editable primitives keep a recipe (tool, values, rotation) that is checked by a shape signature (volume, face count, box within 1e-5 of the size); a change too small for that tolerance would not drop the recipe. A rotated primitive can be edited by size, but its position handles are hidden (the base point is in the primitive's own frame).

- Holes (commit `fd26e01`): the opening is assumed flat and square to the axis (a hole through a sloped face is rebuilt with a flat cut); a plain through hole opens on the side that runs toward the negative axis direction; "through" is the depth that reaches the far side along the axis (`pass_length`, first exit of the axis line past the cut), so a body with a gap beyond the hole reports the first gap; a hole split into two half-cylinder faces is not recognised (treated as a slot); Edit hole edits one hole at a time and takes a countersink only when no counterbore is present; the drag-time dimension labels may lag one preview behind.
- Point-pick snapping offers every hole centre without the hidden-point test (a centre sits at mid-depth inside its hole, behind the face under the pointer), so a hole directly behind another feature on screen can be snapped to within 12 px (`reference.ts`).
- Handle-drag speed (commit `50f8a38`, bracket demo plus an added box, synthetic 40-step drag at 16 ms): before, every pointer move queued a preview and the core answered them in order (about 80 ms each: 9 ms operation, 80 ms meshing), so the last reply of a 40-step drag arrived 2.8 s late and nothing showed until the pointer rested. After, one preview is in flight and the newest waits (latest wins): about 32 ms per round trip (7 ms operation, 17 ms meshing, 1 ms upload and show), and a move arrow slides the moving bodies on the client with no wait. Which bodies move is read off two consecutive previews of the same drag (their centres shift along the arrow), so the first two frames of a drag show the plain previews. Resize grips have no client-side approximation: their round trip is already about 32 ms, under the 100 ms target. Timing hooks: `window.__perf` (per-preview round trip, show time, core timings) and `window.__slid` (client slides) in `main.ts`.
- Preview meshes carry no per-edge drag directions (`tessellate(preview=True)`), so an edge picked on a preview cannot start a fillet drag until the preview is committed.

- Dimension editing (commit `70fd100`): the draft angle edit assumes the Z pull direction and only shows for flat faces within 45 degrees of upright; an edge length moves the flat face at its far end (flip: the near end) and so changes every edge on that face; a face distance or hole distance moves the last selected item (flip swaps) and does not move anything attached to it; the hole-to-face distance is not editable.
- Dimension editing: after a hole diameter or hole move edit the selection is empty (the tools track no face), so the dimension disappears until the hole is picked again.
- Move arrows are a fixed 80 px long on screen (`MOVE_ARM_PX` in `manipulator.ts`) and are drawn without depth testing, so bodies never hide them; picking uses screen distance only, before any body pick. Where a move arrow overlaps a resize grip (origin on a size handle), the rule is: the head half of the arrow wins, the arrow's start does not, so the grip stays reachable (`pickScore`). The owner grabs arrowheads away from grips, so this is a safety rule only.
- Push/pull cut: a negative distance that would remove the whole solid (a full face pushed through its own body) is refused with an error rather than leaving an empty model; in a drag the last distance that worked is kept. A cut larger than the material below the face cuts through and ignores the excess.
- Kept sketches: stored per history state (deep-copied, trimmed with the 50-step history), so a long session forgets sketches that exist only in forgotten states; sketch ids come from a counter saved with the autosave and are never reused. Sketches are not written into saved model files (open file/demo starts with none). `sketch_keep` with regions on a sketch with no closed zone keeps it and makes no faces (facesMade 0).
- Sketch requests carry the sketch's id as `sketch_id`, never `id`: over the socket every request has its own `id` (the reply is matched by it), which silently replaced a sketch id of the same name; unit tests that call `Session.handle` directly cannot see that, so one test now sends a correlation `id` too. Sketch placement: the main button is Sketch On Geometry. With a face it sketches on it; with one edge selected it starts a sketch on the plane square to that edge with its origin at the middle of the edge (the middle of a curved edge by parameter; for rail and path profiles); with three vertices, or an edge and a vertex, extra buttons offer a plane through them; normal to a curved edge uses its tangent there, and the plane's x direction is picked from the world axes.

- Sketch Select tool: a click adds to the selection and a click on a selected item removes it (no Ctrl/Shift needed); empty space clears it. Dragging an unselected item moves only that item; dragging a selected one moves the whole selection.
- Sketch solver requests leave out projected reference curves and fixed points no constraint uses (`forSolver`), because the solver has a limit on unknowns. A constraint to a reference curve keeps that curve in the request.
- Sketch box selection: dragging on empty space with the Select tool draws the same box as the 3D view (solid left to right = window, dashed right to left = crossing) and selects only sketch points and curves; it replaces the selection unless Ctrl/Shift is held. Curves are tested as 48-segment polylines.
- Leaving a sketch (Escape, Discard button, starting another sketch) asks first when a new sketch has drawn geometry or a kept sketch has changes; the page-unload warning is unchanged.
- Project model edges: a tilted arc or other curved edge becomes a spline through about 24 samples per turn (33 for other curves), so it is an approximation of the true ellipse arc; a curve seen edge-on is left as its end points.
- Edit hole `start` (entry-end depth handle): the cut spans [start, end] along the axis and a skin of material is left above it; any counterbore or countersink at the opening is filled and not recut while start is above 0. The start is a parameter of the edit session only: a hole with a skin reads back as a closed internal void (no opening), so it is not found by the hole tools on the next selection, and the form's start returns to 0 for any hole that is read back. Alternative not built: measuring depth from the entry for a through hole.

- Move/Rotate (`move_body`): the rotation rings are drawn in world axes and their grips move along a straight tangent, so a large drag drifts off the circle; rotations apply about each body's own centre in the order X, Y, Z, then the move. The old `rotate_body` stays registered (hidden) for old documents and rotates about the origin. With nothing selected, tools that act on every body (move/rotate/scale/offset/arrays) are offered only when the model has a single body; the core still runs them on a multi-body model if asked.

## Random body colours

- Each body's colour depends only on its stable id: hue = id * 137.508 degrees (+20), saturation 32-42 %, lightness 62 % upward, raised per hue (up to 80 %) until contrast against #1b1d22 is at least 7:1. Blue hues therefore end up lighter than others. Tested for ids 1..500.
- After about a dozen bodies, hues of non-consecutive ids can sit close together; colours are distinct, not unique.
- The surface uses per-vertex colours on a white base, so lighting still applies; loose faces and sheets with no body keep the steel-blue. Colours are not saved in the document and there is no per-body override yet.
- In the body list the name colour overrides the grey of hidden bodies only when visible (hidden rows stay grey, no dot).

## Glossy plastic look (semi-gloss body material)
- Bodies are drawn with a physically based material from `app/src/materials.ts`: the default 'plastic' (Plastic, semi-gloss): roughness 0.4, metalness 0, clearcoat 0.35, clearcoat roughness 0.3, reflection strength 0.8, density 1050 kg/m3 (as for ABS). Reflections come from a soft studio environment generated in code (built once, first use). Lights are lowered while it is on (hemisphere 0.5, key 1.0).
- Setting 'Glossy plastic look' (default on) switches back to the previous flat look when off, for slow graphics.
- Limits: density is stored but unused (no mass yet); there is one material and no way to choose or assign it per body; the look uses no tone mapping, so highlights can brighten flat top faces; the colour vertex tint is multiplied into the reflection too, so very light body colours look paler than flat; sketch overlay not re-checked visually after the change (it uses separate materials).

## Material list and the Material setting
- Global setting 'Material' (default ABS) picks the look for all bodies; there are no per-body materials. Entries (kg/m3, roughness): PLA 1240 0.38, PETG 1270 0.30, ABS 1050 0.40, ASA 1070 0.45, Resin standard 1100 0.25, Resin tough 1150 0.25, Steel mild 7850 0.40, Steel stainless 8000 0.30, Aluminium 6061 2700 0.35, Copper 8960 0.25, Gold 19320 0.15, Silver 10490 0.12, Titanium Ti-6Al-4V 4430 0.48, Cobalt 8900 0.30.
- Densities are typical values (each entry has a range note); photopolymer resins vary about 1050-1250 by product. Density is stored but not used: there is no mass calculation yet.
- Plastics and resins are tinted by the per-body colour (Random body colours); metals show their own colour and ignore it (the body list keeps its colours). Glossy plastic look off gives the old flat look for every material.
- Lustre is judged by eye against the RoomEnvironment studio; steel, stainless and titanium look similar apart from brightness and warmth.

## See-through bodies and Focus

- Each body row has a See-through (X) toggle and a Focus toggle (all other bodies see-through, with a memory so a body ghosted by hand stays ghosted when Focus ends). View only and per session, like hiding; ids are stable across edits and removed bodies are pruned.
- Ghost bodies use the surface material at the See-through opacity setting, drawn as separate index ranges of the same geometry (no mesh rebuild). Their edges are drawn like any other body's edges (not dimmed).
- Picking: a see-through face never hides anything behind it. A click lands on the nearest solid face, else on the nearest see-through face, so a ghost face with a solid body behind it cannot be clicked directly (use Alt+click to cycle or pick its edges). Edges and vertices of ghost bodies stay snappable but are still hidden by solid faces in front of them.
- While bodies slide (move tool preview) ghosting is paused until the slide ends.
- Sketch curves still snap to model geometry only through Project model edges.
## Display data cache (tessellate.py)
- Per-face and per-edge display arrays, edge drag directions, planar normals and hole centres are cached in `tessellate.display_cache`, keyed by the shape (TShape, location, orientation) plus the mesh deflection (and the triangulation's own deflection for faces; neighbouring faces for edge directions). Bounded to about 400,000 triangles and edge segments, least recently used first; the arrays in it are shared, never modify a Mesh's arrays in place.
- A cached face is only reused while the triangulation deflection is the same as when it was stored; a model that grows enough to change the power-of-two deflection re-extracts everything once.
- Still per-body cost on every commit (N=150, about 300 ms): body numbering `_solid_indices` ~65 ms, the OCCT mesh pass ~60 ms, building ids, ranges and dicts ~100 ms, bounds, encoding ~15 ms. The reply no longer waits for the autosave: the snapshot is queued after the reply is built; the background write of the whole model still takes ~260 ms at N=150 and delays an immediately following request.
- Per-body cost trimmed: the OCCT mesh pass now runs only on solids with a face that has no triangulation at the current deflection (`_needs_mesh`, so a face meshed coarser than the wanted deflection is re-meshed), and `_solid_indices` takes each solid's ids from the growth of a running indexed map instead of looking up every sub-shape (falls back to the lookup version when the model has shapes outside any solid). At 400 bodies a warm preview went from about 1500 ms to about 730 ms; both steps are still O(bodies) per request, only cheaper.
- `Topology.edge_faces` is very slow when called for every edge of a many-body model (iterating the ancestor lists, about 13 ms per 100 edges); tessellate uses its own one-pass lookup.
- Sketch grid (commit `e5e02ca`): each pixel now finds its own point on the sketch plane (a screen-filling quad, no huge plane), set just before drawing so it cannot lag the camera. Meant to stop the grid wobbling while the camera glides after an orbit; not hand-checked during a glide. The reported lock-up when the grid is turned off mid-wobble was not reproduced, so it may still exist.
- Profile regions of kept sketches are picked in the 3D view by a ray test against the tinted fills (commit `49057a9`): a click that finds no edge or point, or a face not in front of the fill, opens that sketch's extrude dialog (distance, mode, both directions, preview). It is not a push/pull drag from the face and does not select the region as a face for other tools. Checked once in Chrome with see-through on; a region exactly coplanar with a model face is picked only when it is not behind it.
- Sketch planes from a face (commit `fd4d6d7`): offset and angled planes work only on flat faces; the angle turns about the face plane's own x axis (a chosen edge as the hinge is not offered yet), and a moved or turned plane has no face outline reference. The tangent plane needs a vertex selected on the face and takes the surface normal nearest that vertex. The buttons are not hand-checked in the app.
- Edge centres (commit `03250c6`): each circular or elliptical edge carries its centre in the mesh data and is a snap anchor named Centre; it is not a selectable item, and the centre dots shown on hover still belong to holes only. Conical mouths have no centre. Not hand-checked in the app.
- Selection filters (commit `8f173e0`): the F, E and V keys act only while a box drag is in progress (they stop being tool shortcuts for that moment). Select similar compares faces by direction (flat faces, within about 0.001 degrees) or area (0.1 percent) and edges by length (0.1 percent), across all bodies, from the page's own mesh; it is not hand-checked in the app and has no "same radius" or "same body" choice.
- Hole ends (commit `5967567`): a through hole with a step at one end only is read with that end as its opening (the wider end), so "far end" means the end opposite the one the hole is read from; the far-end stage depth is measured from the far face. Steps have typed depths only, no drag grips; a countersink is replaced by another countersink but a counterbore is refused over a countersink at the same end. Round holes only; squares and slots still use their faces' own push and pull. Not hand-checked in the app.
- Sketch plane gizmos: an arrow along the plane's normal and a turning ring about each of its x and y axes appear while a sketch is open (not on unrolled curved faces) and move the plane with everything drawn on it, so a face outline reference moves too. The Offset From Face and Angled From Face buttons and the offset box are gone (the core still accepts those requests). The ring drag has no angle snapping. Not hand-checked in the app.
- Sketch grid: rays that meet the plane behind the camera are discarded, which removed a mirrored second grid at grazing angles. Not hand-checked in the app.
- Primitive rotation: box, cylinder, sphere, cone and torus take rx, ry, rz (X, then Y, then Z, about the base point) and show three rings. While turned, the low-face grips that also move the base point are hidden, and the "base point" anchor picker still measures from the unturned shape. Not hand-checked in the app.
- Body list Duplicate puts the copy exactly on top of the original (no offset) as a plain solid with no primitive recipe; Delete and Duplicate are not hand-checked in the app.
- Draft and Inset face edges gizmos: the draft ring sits on the first selected face and its grip rides the face as the angle changes; the inset arrow is placed at the start of the chosen loop and points to the face's centroid side (can mislead on strongly concave outlines). The Inset "every edge" toggle is a click marker at the face centre and also a plain number (all_loops) in the form. Not hand-checked in the app.
- Cut and Split with plane gizmos: an arrow slides the plane along its untilted normal and two rings tilt it (tilt_u, tilt_v) about axes through the point of the plane nearest the model middle; the tilt axes are picked from the normal, not from the view. Not hand-checked in the app.
- Cut and Split with plane now cut only the selected bodies (or the bodies of selected faces) and every body when nothing is selected; a body the plane misses is left as it is. Refine bodies (was Unify faces) works the same way. Not hand-checked in the app.
- Sketch card: the Extrude and Revolve sections are gone (profiles are extruded from the Sketches list for now). The header has gizmo show/hide, pick base point and pick move to location buttons: the plane moves by the vector from the picked base (or its own origin) to the picked destination, snapping to the reference points the point picker offers; the move is not undoable with the sketch's own undo. Finish and Discard sit right under the header and report a failure in the status line; the owner's report that they did nothing could not be reproduced. Right-click (not a right-drag) in a sketch ends the line being drawn and returns to Select. Checked in Chrome: card layout, pick and move, right-click.
- Project model edges (sketch card) is a pick mode: click faces and edges, then the button again or Enter projects them, Escape cancels; the core projects only the picked items. The projection notes about edge-on arcs show in orange (warn style) instead of red; any later message replaces the orange. The old whole-model projection is no longer reachable from the card. The owner reported the card going unresponsive after the projection message; I could not reproduce it (Check sketch, Finish and Discard all worked after projecting 70 edges with the same message).

- Picked sketch regions: the pick is a real commit (undone when you click away unused), so it adds one undo step if a tool then uses it; a region whose face merges oddly with an imprint host may not be found again by area and centre, then nothing is selected.

- Live sketch profile faces (commit `42956f8`): after every solve that is not a drag the whole sketch is sent to the core to split into regions (one extra request per solve); a very large sketch may lag, and the tint is not updated during a drag. Not checked in the app.
- Project file (.plbl): a saved project holds only the current state, not the undo history, and opening one replaces the model. Autosave writes one such file per undo step, so a crash restore keeps the undo steps. Sessions written by the first autosave format (bare BREP files) are still restored. Opening a file from a newer release is refused.
- Rotation rings are drawn at half the shortest side of the 3D view in diameter whatever the zoom or the size of the body (trial); a ring no longer hugs a small body.

- Datum planes: each is drawn as a fixed square of 120 model units whatever the size of the model, and they cannot be dragged or picked in the view yet (made from the command search: origin planes, the selected face, or midway between two selected faces; the core also moves one by an offset). Names are not forced to be unique.

- Symmetric push/pull (Shift while dragging a face): one face needs a matching face on the other side of the nearest parallel origin or datum plane (matched by area and centre within 0.001), otherwise it says so; Shift+press on a face over a selection now starts the drag instead of an additive box select (Ctrl still adds). Two opposite faces are accepted by the Push/Pull tool only when the drag is symmetric.

- Mirror mode: it repeats added and removed material across the plane after tools and sketch extrudes; it does not make an unsymmetric model symmetric when turned on, does not mirror whole-body moves, copies or rotations, and a change that cannot be repeated (the boolean fails) is refused with a message. Each change costs a few extra booleans, so previews on large models are slower while it is on.

- Dimension and grip outlines: dimension lines, arrowheads, values and handle grips carry a dark outline so they stay readable over light bodies (`dimensions.ts` `lineHalo`, `HALO_COLOR`; `manipulator.ts` `HANDLE_OUTLINE`). The outline is thin and 60% opaque (approved); only revisit if visibility or looks complain again. Grip stems and rotation rings have no outline (WebGL lines are one pixel wide).

- Sketch strip constraint buttons are never greyed out (owner, 2026-10-23); clicking one the selection does not take shows an orange note. What each takes, kept from the old greying (`CONSTRAINT_OPTIONS` in `sketchconstraints.ts`; `chooseConstraint` still computes `enabled`): Horizontal / vertical, Horizontal, Vertical: one or more lines (Horizontal and Vertical also two points); Coincident: two or more points, or points and curves (point on curve); Fixed: one point; Parallel, Perpendicular: two lines; Equal: two lines or two curves; Tangent / collinear: two or more lines (collinear) or a curve with a line or curve (tangent); Point on: one curve and one point; Midpoint: one line and one point; Lock: one curve; Symmetric: one line and two points; Length / distance, Horizontal distance, Vertical distance: one line or two points; Point to line distance: one line and one point; Angle to horizontal axis: one line; Short radius: one ellipse; Radius: one arc or circle; Diameter: one arc or circle; Angle: two lines; Dimension: whichever of the dimensions fits.
- Sketch dimension placement: a dragged dimension stores `place` (sketch coordinates) on its constraint (display only; the solver ignores it). Without one, a length dimension picks the side whose probe point (about 40 px from the line's middle) is outside every tinted profile region, and a circle's leader picks the first of right, left, up, down that ends outside the regions. The regions come from the last `sketch_profiles` reply, so the first draw after a change can still use the previous regions (`sketch.ts` `outside`).
- Dimension hit lines: the line across a circle or to its centre has no hit area, so the centre and the curve stay selectable under a radius or diameter dimension (`dimensions.ts` `lineHits`); only the text and the leader beyond the rim drag or open the editor.
- Measure pick (M) during push/pull: the measurable edges now come from the face pressed even when companion faces are selected with it (before, two or more selected faces gave none). This is a guess at the reported case (M offered no perpendicular edge); not hand-checked with companion faces, and a push started from the arrow handle has no measure pick.
- Linear array grid: `rows` defaults to 3, so an older saved history that ran a linear array without `rows` replays as a 3-row grid. The corner grip changes count and rows by fractional steps that the core rounds. Introduced in the linear array grid commit (d7aacc6).
- Array apply or discard: the click that raises the prompt is not carried over after Apply or Discard (ids in a preview differ from the model's); only the three array tools ask; other forms still close silently on a selection change. Introduced in the array prompt commit (837393d).
- Points on an ellipse use hidden focus points and a helper point per constraint (`solver.py` `_point_on_ellipse`): the foci sit on the longer axis as found when the constraint is added, so an ellipse whose axes swap length while the sketch is open keeps the old focus axis and may fail to solve. An ellipse drawn before the four axis ends existed gets hidden ends for this, from its stored short radius. Introduced in the ellipse quadrant points commit (4c3937c).
- Moving a kept sketch moves its plane only (`sketchmove.py`): the curves keep their place on the plane, one sketch at a time, and fixed projected model edges inside it move with it instead of staying on the model. Introduced in the sketch move commit (a6edc14).
- Status messages are recorded by watching the top bar's status line (`messagelog.ts`): a message set without the error or warning class and without the word "Warning:" is not kept for Copy diagnostics. Introduced in the message log commit (c5390bf).
- Move/Rotate on edges (`move_edge.py`, used by `move_body.py`): snaps are only offered for flat faces beside the first edge, with a 3 degree pull (`SNAP_DEGREES`); the gizmo takes its axes from the first selected edge; in edge mode the form still shows Rotate Y and Z, which do nothing, and an arrow's label shows the distance moved in that drag, not a form value. Straight edges only, and the faces re-fit through the Stretch code, so a move that would bend a face with more than three corners off its plane is refused. Introduced in the Move edge commits (hashes to add).
- Trim tool: cuts only at crossings with lines and circles (arcs, ellipses, splines are not crossing candidates) and acts on lines only; a crossing within 1e-6 of an end is ignored. Marked pieces are remembered only until the tool changes or undo is used (this commit).
- Ellipse axis lines: Delete on an ellipse leaves its two construction axis lines (they hold the axis end points); delete them separately (this commit).
- Per-body material changes mass only, not the look: all bodies share one surface material in the viewport, drawn with the Default material's numbers (this commit).
- Tauri shell (`desktop/`): the core's page is served from `http://127.0.0.1:PORT/` and the window navigates to it, so saved page settings are per port (8765 when free, else a random one, which loses them); the packaged core is only killed by the shell on a normal exit (after a hard kill it ends itself 20 s after the window's connection drops); the macOS and Linux shells are built only by the manual `desktop` workflow and were not run here (this commit).
- Sketch solver output guard: a solved point that is not a number or lies beyond 1e9 makes the solve fail instead of reaching the 3D view; the 1e9 limit is a guess (commit for the white-viewport investigation, hash to add).
- Point freedom colouring: a sketch the solver reports with no degrees of freedom colours every point as placed at once; otherwise points are tested one by one within a 1 second budget and later points stay uncoloured in a very large sketch. A circle with a placed centre but a free radius still colours as placed (this commit, hash to add).
- Resize fillet on a tangent chain (model agent, this commit): the chain is the fillet faces tangent-connected to the picked one with the same radius (cylinder, sphere or torus minor radius within 1e-6); strips with exactly two other tangent neighbours define the sharp edges to re-round; variable radius is refused on chains.
- Circular array about a picked edge stores the edge id (axis_edge) of the model the form was opened on; it is not tracked if the model changes (this commit). The count grip is dragged along the arc and one step of arc equals one copy, so with 360 degrees the grip moves while the count changes.
- 3dm import and export (formats agent, this commit): faces are converted from NURBS surfaces and 3D edges with a 1e-3 mm sewing tolerance; meshes and curves in the file are skipped, and export writes triangle meshes (0.01 mm, 0.3 rad), not B-reps.
- IFC import and export (ifc agent, this commit): import rebuilds solids from IfcOpenShell triangles (sewing tolerance 1e-3 mm, coplanar faces merged back, curved faces stay faceted); products that fail to triangulate are skipped and counted; openings and spaces are skipped. Export writes faceted B-reps (0.005 mm, 0.1 rad) as IfcBuildingElementProxy in IFC4, no materials, no properties, no storeys. The package is an optional extra.
- Tangent circle and tangent arc between curves (arctools agent, 3971dad): arcs are treated as their whole circles and lines as infinite when the tangent circle is solved, so a touching point can lie on an extension of a curve; the nearest-centre choice is by the pointer only.

- Tangent arc start (arctools agent, 4c9b381): only the end of a line or arc can start one; the tangent constraint is added even when automatic constraints are off.
- Push/pull on faces of several solids (for example the Coplanar chip) pushes each solid on its own with the same distance; faces in open shells are still refused and solids that end up overlapping are not fused. (commit: see git log for "Let push/pull move coplanar faces of several solids")
